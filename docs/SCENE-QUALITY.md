# 场景品质与生成标准

## 本轮目标

将已有树木、地形、水文和世界内容库组合成可读的场景。品质不能仅由资产数量、
三角形数量或使用 `MeshPhysicalNodeMaterial` 来判断；必须检查最后输出的画面。

本轮没有替换渲染器，没有引入外部资产依赖，也没有重写地形侵蚀或水文算法。
新地貌专用算子、任意河湖图编辑器和可视化场景编辑器仍是后续工作。

## 模块边界

| 模块 | 输入与职责 | 不应承担 |
|---|---|---|
| `world/WorldShowcase` | 数据化默认参数，交给既有 Params 解析 | 构建网格或单独运行世界生成 |
| `world/TerrainSurfacePalette` | 独立的线性反射率色板，野生林地使用较暗风化岩面 | 改变地形高度或生境规则 |
| `world/HabitatModel` | 连续干湿生境、物种权重、草团规则；同公式用于 CPU 测试和 GPU | 模型几何、季节或相机状态 |
| `gpu/HabitatTSL` | 将生境数学绑定为 TSL，采样预烘焙斑块噪声 | 维护另一套生态公式 |
| `FoliageCards` | 从相同叶簇源捕获颜色/覆盖和表面信息 | 改变散布位置或生长骨架 |
| `VegetationLodBudget` / `Forests` | 确定性细节名额、完整后备表示与 GPU 间接绘制 | 用丢弃实例来限制 Hero 成本 |
| `MagicRuinsStyle` / model kit | 石材、地衣、水晶、符文几何与表面品质 | 站点规划和植被排除规则 |
| `MagicRuinsApproachPlanner` | 只读地形/碰撞，选择入口视点与朝向 | 移动地形、遗迹或创建新的随机流 |

### 生境与概率

保留原六类 biome 的纹理/实例池编号，用独立连续生境叠加干旱与湿润区域。
植物类别必须先得到最终强度，再用同一组强度决定接受和类别选择。
禁止用仙人掌的接受率生成候选，随后从未限制的蕨类/花朵权重中选择。

草团固定在世界坐标：约 22m 的群落斑块包含约 1.8m 的草团与间隙。
沙地允许真实裸露，不能因为相机靠近就提高最低草密度。显式 include/exclude
继续由 LandscapeProfile 解析，排除优先，已有铺装与内容占地排除不绕过。

水岸读取实际渲染水位，不能直接用填洼场 W 或固定 LAKE_LEVEL 替代。
干地的水位代理约在地表下 2m；湿边阈值必须小于这一间隔，避免整片干地变湿。

### 叶簇与远景

原 RGBA 贴图接口继续有效：RGB 为 sqrt(albedo)，A 为叶簇覆盖。
新增一张伴随表面贴图：RG 为捕获平面法线 XY，B 为粗糙度，A 为局部 AO。
两次捕获使用完全相同的几何、投影和季节落叶判定，不额外消耗随机流。
颜色与表面边缘分别扩散，避免透明边缘的错误法线和粗糙度渗入 mip。
旧的普通 Texture 调用仍走兼容路径。

离屏烘焙必须在成功与失败路径中恢复 renderer 状态，并释放临时材质、渲染目标和
独占的捕获源几何；不能销毁借用的 bark/foliage 纹理或运行时资产池。GPU readback
已返回独立数组时直接复用，避免再次复制整张贴图。

远景树冠壳使用六类 biome 的代表物种混色与季节权重，不是逐棵树种颜色的精确烘焙。
冬季无叶的阔叶树不能继续生成/提交透明的实体叶和空卡片树冠。

### 细节预算与阴影

Hero 名额保持每物种每结构变体 5 棵。GPU 使用距离优先、实例身份破同距的
packed key，通过 atomic-min 插入保留最近 K 棵，不依赖 GPU 调度先后。
未获得名额的近树必须进入 R1，并禁用其 Hero→Near 淡入边界，不能变成透明树。
Near→Mid 的互补淡出仍保留。

近景阴影统一由 R1 枝干/叶簇与冠层代理承担，不随 Hero 名额第 5/6 位交换。
这样高面数 Hero 不需要再为四个阴影级联重复提交，名额交换也不改变阴影表示。
本轮树木 cull 最低需要 10 个 storage-buffer 绑定；启动前必须报告不支持的设备。

### 遗迹与起点

石材维持单块 300 tris 的共享实例几何，表面微细节由材质负责。
地衣沿地形细分到不大于 0.55m 的单元，单站点最多 16k tris/一个 draw；
不能用抬起的大三角扇覆盖地面。门户只增加一个实例化符文 draw。
发光强度必须保留水晶切面和门环颜色，不以大片白色 bloom 代替细节。

碎石优先在墙脚成组，晶簇避开入口轴线和仪式中心。起点沿入口多点检测：
干地、坡度、碰撞、门户中心及下方两条地形视线；保持 1.7m 人眼高度和步行模式。
如无无遮挡点，选择遮挡最少的安全点；无安全点则回退全局出生逻辑。

## 验证与复现

```bash
npm run test:quality
npm run test:world
npm run build
```

CPU 合同测试不能替代真实 GPU 验收。提交前至少检查：

完整世界的资产池较大，批量视觉验收应关闭已完成的测试标签页，再打开下一个案例。
如果连续导航后出现 `Array buffer allocation failed`，先关闭旧预览页并在新页复测，
同时检查进程内存；不能直接把后台 FPS 或内存压力归因于某一张新增材质贴图。

| 检查 | 固定案例 / 方法 |
|---|---|
| 遗迹整体与起点 | `?showcase=enchanted-river&preset=low&freeze=1` |
| 同场景回归 | `?world=magic-forest-ruins&terrain=laas&seed=42&preset=low&freeze=1` |
| 干湿生态分区 | `?showcase=oasis-sanctuary&preset=low&alt=8&x=930&z=160&yaw=2.25&pitch=-0.18&freeze=1` |
| 秋冬叶簇 | `?scene=veghero&species=birch&season=autumn&seed=84&preset=low&freeze=1`，再检查 winter |
| 草团与 LOD | 同一场景在近、中、远距离移动，观察缺口、透明边缘、贴地和阴影跳变 |
| 生产部署 | `npm run preview`，访问 `/codex-world-factory/` 下相同参数 |

检查控制台不得出现新的 WebGPU validation error、绑定越界或 shader 编译失败。
性能比较必须保持前台、相同设备、视口、分辨率、机位、时间与质量档；后台节流 FPS
不能作为性能结论。HUD 总 tris 包含多 pass，不等于单棵树或一帧可见模型的资产面数。

本轮改变生态分布规则和遗迹装饰，因此旧 seed 在新版本中可能出现不同的植物与装饰。
保存 `commit + 完整URL` 才能跨版本复现；季节仍只改变表现，不重抽地形与植物位置。
