# 程序化自然素材开发标准

本文是 Codex World Factory 中树木、灌木、草本、花卉、蕨类、蘑菇、岩石、枯木和林地碎屑的强制开发标准。城市建筑、道路和遗迹等硬表面资产使用独立标准，不应把两类参数混在同一个配置对象中。

目标不是让每个距离层都提交最高面数，而是让同一素材在近景具有可信的轮廓、曲面与 PBR 响应，在远景保持相同的体量、颜色和随机身份。

## 一、七项准入门槛

一个新增或重做的自然素材必须同时通过以下七项门槛，才可以进入默认世界配方。

1. **独立身份与确定性**
   - 必须有稳定、唯一的素材 `id` 和表面配置 `profile.id`。
   - 生成器只能使用注入的 `Rng` 和命名 seed stream，禁止使用 `Math.random()`。
   - 表面升级不得改变既有位置、地形采样、树木骨架或后续 seed stream。

2. **完整 PBR 表面**
   - 材质至少提供颜色、法线或 bump、粗糙度、AO 和介质高光响应。
   - 树皮使用 `texA = sqrt(albedo.rgb) + cavity`、`texB = normal.xy + roughness + height` 的打包契约。
   - 叶片、草和花瓣必须有受控的薄表面透光；岩石、木材和地面碎屑不得复用叶片透光模型。
   - 非金属自然素材 `metalness` 必须为 0；clearcoat 只能表达蜡质叶面、树脂或潮湿薄层，禁止用来制造塑料感。

3. **可读微表面**
   - Hero 层必须让纹理高度实际参与浮雕视差或几何位移，不能只改变颜色。
   - 树皮裂缝需要法线、cavity 和直接光下的裂缝暗化共同表达。
   - 岩石需要矿物颗粒/孔洞 bump；叶片需要中脉、侧脉和细胞级起伏；草叶需要中肋；花瓣需要放射叶脉；蘑菇需要菌褶或表皮孔隙。

4. **近景曲面与真实轮廓**
   - 树干不得是完全规则圆柱：使用椭圆截面、缓慢扭转、多频轮廓扰动、根颈和枝杈连接。
   - 阔叶 Hero 叶片至少使用 5 列横向采样和 9 段纵向采样，并支持厚度、卷曲、杯状边缘和左右差异。
   - 裂叶树种必须生成真实叶窦轮廓，不能用透明纹理伪造全部叶缘。
   - 针叶 Hero 几何至少使用 2 段曲线和 2 个交叉面，并在针尖收细、弯曲。
   - 岩石必须使用焊接网格、宏观位移、层理、断面和洞隙；枯木必须保留不规则截面和破断端盖。

5. **物种/类别特有缺陷**
   - 树种必须拥有独立树皮配方，不得因为颜色接近就复用不相干树种的高度场。
   - 活树根据物种配置树根、树瘤、伤疤和剥落；枯立木强调纵裂、腐朽、断枝与剥皮。
   - 灌木和蕨类即使运行时使用捕获卡片，也必须从该类别的高细节实体源几何生成 atlas。
   - 叶簇卡片必须保留源表面的法线、粗糙度与 AO，不能只有颜色/透明度后将整个卡片调成近乎漫反射。
   - 生境与植物强度在独立的 `HabitatModel` 中定义，接受概率与最终类别选择使用同一组强度。

6. **分级表示与硬预算**
   - Hero：0–28 m，真实树皮轮廓、缺陷/根系、实体叶或针叶、完整 PBR。
   - Near：28–150 m，完整枝干和捕获卡片，最多三步浮雕视差。
   - Mid：150–460 m，简化枝干/卡片，保留法线、粗糙度与 AO，关闭视差。
   - Far：460 m 以外，使用可重新受光的八面体 impostor。
   - 过渡必须使用重叠 band 和互补抖动，禁止硬切换。
   - 每个树种每个结构变体最多提交 5 个 Hero 实例；实体叶锚点必须有显式上限。
   - 超出 Hero 名额的近树必须完整回退 Near，不得丢弃或继续执行只属于 Hero 过渡的透明淡入。
   - 近景阴影使用独立于 Hero 名额的 R1 表示；远景树冠颜色必须消费同一季节外观规则。
   - 当前参考单树预算：云杉约 261k、松树约 418k、山毛榉约 549k、白桦约 223k、喀斯特树约 121k、枯立木约 8k、古橡树约 633k、柳树约 341k 三角形。新配置若超过参考值 25%，必须在评审中说明画面收益。

7. **自动化验证与可视检查**
   - 必须验证相同 seed 下基础版和增强版骨架完全相同。
   - 必须验证顶点为有限数、索引有效、LOD 面数单调下降、表面 profile 完整且 ID 唯一。
   - 新叶形应有轮廓/曲率测试，新针叶应有段数和交叉面测试，新材质应验证 Physical Node 材质和微法线节点。
   - 提交前必须运行 `npm run test:assets`、`npm run test:world` 和 `npm run build`。

## 二、代码分层

```text
Species / Understory
  只描述生长语法、体量、叶形基础比例和树皮层编号
        │
        ▼
VegetationProfiles
  描述 PBR、Hero 曲面、缺陷、根系、叶/针叶细节和面数预算
        │
        ├── TreeBuilder / TubeMesh / LeafMesh：实现真实几何
        ├── BarkSynth / VegMaterials：实现高度场和 PBR
        └── FoliageCards / Impostors：从同一素材生成远景表示
```

生长语法和表面实现必须分离。需要增加树皮深度、叶脉或叶片段数时，不应修改 `Skeleton.ts`；需要改变树冠结构时，也不应把参数塞进材质 profile。

## 三、树种开发流程

1. 在 `Species.ts` 中增加生长参数和唯一的 `barkLayer`。
2. 在 `BarkSynth.ts` 中增加可平铺的树皮高度/颜色配方。
3. 在 `VegetationProfiles.ts` 中注册完整 profile，明确四级材质行为和 Hero 预算。
4. 阔叶选择通用曲面叶、裂叶或披针叶参数；针叶选择针长、段数、交叉面和弯曲。
5. 使用同一个 seed 构建 `heroSurface=false/true` 两棵树，确认骨架和锚点不变。
6. 运行 `tools/herotris.ts`，记录树皮、卡片和实体叶的面数拆分。
7. 更新对比场景或 gallery，近距离检查裂缝深度、叶缘、背光、根颈和枝杈连接。

## 四、小型素材开发流程

- 灌木、蕨类：优先提高 atlas 捕获源几何，运行时卡片保持原预算。
- 仙人掌和其他多肉植物：真实轮廓必须由肋、柱、掌片或莲座几何形成；材质负责蜡质高光、
  微小刺座和表皮细胞，不得用普通树叶卡片伪装体积。生态出现条件必须留在 scatter/habitat
  层，素材生成器本身不得读取地形或生物群系。
- 草、花、蘑菇：用少量曲面段数解决轮廓，用 bump/roughness/translucency 解决微观材质，禁止为不可见细节堆叠大量三角形。
- 岩石：同一位移场在不同细分级别重算，确保 LOD 体量一致；颜色、层理、苔藓和微 bump 由材质层完成。
- 枯木、树桩、树枝：复用枯立木表面契约，但根据距离关闭视差；腐朽和苔藓通过稳定数据通道控制。
- 落叶、树皮碎片和细枝：使用 Physical Node 材质和类别特有 bump，同时保持实例化绘制。

## 五、提交检查清单

- [ ] 素材 ID、profile ID、树皮层唯一。
- [ ] 没有新增 `Math.random()` 或匿名随机流。
- [ ] 同 seed 的位置/骨架/锚点未因表面升级改变。
- [ ] Hero、Near、Mid、Far 的功能和预算明确。
- [ ] PBR 至少覆盖颜色、微法线、粗糙度和 AO。
- [ ] 薄表面透光、clearcoat 和视差只用于正确的材质类别。
- [ ] 近景轮廓不是纯卡片或规则基础体。
- [ ] 捕获 atlas 与运行时 profile 使用同一物种配置。
- [ ] 季节变化只修改颜色、覆盖率、透光、粗糙度和冠层代理，不消耗 RNG、不改变骨架或散布位置。
- [ ] 新测试覆盖配置、几何、材质和有限顶点。
- [ ] `test:assets`、`test:world`、`build` 全部通过。
- [ ] `test:quality` 通过，并检查固定种子实机画面的近/中/远距离及逆光；CPU 材质节点测试不能替代 GPU 渲染验收。
